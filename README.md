# Цифровая визитка

GraphQL API профиля, навыков, опыта и проектов. Контракт для Apollo Sandbox:

```graphql
query {
  profile {
    name
    description
    skills {
      name
    }
    experience {
      company
      position
    }
    projects {
      name
    }
  }
}
```

Содержимое визитки лежит в `src/infrastructure/seed/profile-catalog.data.ts`. Это единственный источник данных: при старте приложение применяет миграции и записывает каталог в PostgreSQL

## Запуск

Нужны Node.js 22 и Docker

```bash
cp .env.example .env
docker compose up --build
```

- GraphQL Sandbox: http://localhost:3000/graphql
- Swagger операционных маршрутов: http://localhost:3000/docs
- readiness: `GET /ready`
- liveness: `GET /live`
- метрики: `GET /metrics`

Только база, а приложение локально:

```bash
docker compose up -d postgres
npm install
npm run start:dev
```

## Тесты

```bash
npm run test:unit
npm run test:integration
npm test
```

Для интеграционных тестов должен быть запущен Docker

Unit-тесты проверяют доменные инварианты каталога, сценарии синхронизации и чтения, пробы, request id, ограничение глубины GraphQL и батчинг вложенных данных. База для них не нужна

Интеграционные тесты через Testcontainers поднимают PostgreSQL, применяют миграции и проходят маршруты на живом приложении: GraphQL, sandbox, probes, метрики, swagger, ошибки валидации и not found, идемпотентный повтор каталога, починку изменённой строки и ограничения базы

Pre-commit запускает проверку типов, unit-тесты, ESLint и Prettier

## Логика задания

Визитка — один профиль. Навыки, ссылки, опыт и проекты принадлежат ему. Достижения принадлежат роли, навыки проекта ссылаются на навыки профиля

Запись есть только на старте. Каталог из репозитория — источник правды, база — модель для чтения. Повторный старт с тем же каталогом ничего не переписывает. Если строка в базе разошлась с каталогом, синхронизация восстанавливает данные в той же транзакции

GraphQL не делает один широкий `include`. Корень профиля читается отдельно, а связи подгружают field resolver-ы через DataLoader: один запрос на выбранный тип связи, без загрузки полей, которые клиент не просил

## Консистентность и ошибки

Синхронизация каталога идёт в одной транзакции. До записи берётся `pg_advisory_xact_lock`, потому что при первом старте строки профиля ещё нет и `SELECT FOR UPDATE` её не защитит. Пока транзакция не закоммичена, читатель не видит наполовину записанный профиль

Поверх блокировки стоит версия строки: обновление проходит только с той версией, которую прочитали. При конфликте синхронизация повторяется один раз. Уникальные индексы, в том числе один открытый период работы на профиль и регистронезависимое имя навыка, остаются последней защитой, даже если код обойдёт блокировку

Невалидный каталог не открывает транзакцию. Ошибки GraphQL и HTTP отдаются одним кодом и `x-request-id`: заголовок берётся из запроса или генерируется. Внутреннее сообщение наружу не уходит

Readiness отвечает 200, когда миграции применены, каталог записан и база отвечает на `SELECT 1`. Liveness смотрит, что процесс жив и задержка event loop не выше порога. На остановке readiness сразу становится недоступным, соединения закрываются через shutdown hook
